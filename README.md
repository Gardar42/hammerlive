# HammerLive

HammerLive – информационная система для проведения онлайн-аукционов в реальном времени. Платформа рассчитана на общенациональные торги коллекционными, антикварными и уникальными товарами: в одном аукционе могут участвовать до нескольких тысяч человек, а число параллельных торгов не ограничено. От существующих белорусских площадок HammerLive отличается сочетанием трёх вещей: ставки обрабатываются в порядке поступления и сразу видны всем участникам, торги сопровождаются видеотрансляцией с минимальной задержкой, а расчёты автоматизированы – участник регистрируется с привязкой банковской карты, и средства списываются с победителя автоматически. Доверие между участниками поддерживает единый индекс репутации.

Целевая аудитория – организаторы аукционов (аукционные дома, галереи, фонды), продавцы коллекционных товаров и покупатели, которым важно участвовать в торгах удалённо. Проект рассчитан на 2027–2029 годы: разработка MVP, закрытое бета-тестирование, публичный запуск и выход на окупаемость.

## Структура репозитория

```
api/            спецификация API (OpenAPI 3.0)
config/         docker-compose, переменные окружения, манифесты Kubernetes

src/services/   микросервисы backend (заготовки модулей)

```

## Сборка и запуск

На текущем этапе в репозитории находятся заготовки модулей, поэтому ниже описаны предполагаемые шаги для локального запуска.

1. Установить Docker 24+ и Docker Compose v2, Python 3.12 и Node.js 20.
2. Скопировать `config/.env.example` в `config/.env` и заполнить значения (пароли БД, ключи тестовой среды платёжного провайдера).
3. Поднять инфраструктуру и сервисы: `docker compose -f config/docker-compose.yml up -d --build`. Будут запущены PostgreSQL (в локальном окружении – один сервер с отдельной базой для каждого сервиса), Redis, брокер сообщений RabbitMQ и все микросервисы.
4. Применить миграции БД: `docker compose -f config/docker-compose.yml run --rm identity alembic upgrade head` (аналогично для остальных сервисов с собственной схемой).
5. Запустить веб-клиент: `cd src/web-client && npm install && npm run dev`. Клиент будет доступен на http://localhost:5173, API Gateway – на http://localhost:8080.

Промышленное развёртывание выполняется в Kubernetes, манифесты будут размещены в `config/k8s`.

## Для разработчиков

Backend состоит из микросервисов на Python 3.12 и FastAPI, каждый лежит в отдельной папке `src/services/<имя>` со своими зависимостями и Dockerfile. Состав сервисов соответствует диаграмме компонентов ЛР №3 и пяти архитектурным квантам: «Аукционист» (auction-session, auctioneer-capture), «Участник» (bid-capture), «Потоки участников» (bid-streamer, video-streamer, video-capture), «Отслеживание ставок» (bid-tracker) и «Платёж» (payment); вспомогательные сервисы – identity, reputation, notification. Внешний API отдаётся через API Gateway по REST и WebSocket, сервисы обмениваются сообщениями через очереди RabbitMQ (AMQP): `BidPlaced`, `BidAccepted`, `BidRejected`, `LotClosed`. Каждый сервис, хранящий данные, владеет собственной базой PostgreSQL 16 и не обращается к базам других сервисов; поток ставок для участников хранится в Redis 7. Веб-клиент написан на TypeScript и React (Vite).

Чтобы начать работу: клонируйте репозиторий, создайте ветку от `main` с именем вида `feature/<кратко-о-задаче>` или `fix/<...>`, внесите изменения и откройте Pull Request в `main`. В описании PR укажите, какие требования ТЗ или замечания он закрывает. Прямые коммиты в `main` не допускаются, слияние – после ревью хотя бы одного участника команды. Изменения API сначала вносятся в `api/openapi.yaml`, затем в код.
